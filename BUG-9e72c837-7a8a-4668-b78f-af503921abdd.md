# BUG-9e72c837-7a8a-4668-b78f-af503921abdd

`FS-310-HDS-010-SDS-010-SMS-030` cannot finish inside the suite's budget: its
dispatcher also runs a three-trace shared case whose runtime exceeds it.

## Correction to my first reading

I initially called
`tests/lib/FS-310-HDS-010-SDS-010-SMS-030/FS-270-HDS-010-SDS-010-SMS-040.sh`
a stray duplicate. It is not: it is byte-identical to
`tests/lib/shared/FS-270-HDS-010-SDS-010-SMS-040.sh` and its header deliberately
declares three traces that share it:

```
# GAMP-ID: FS-270-HDS-010-SDS-010-SMS-040
# GAMP-ID: FS-310-HDS-010-SDS-010-SMS-030
# GAMP-ID: FS-320-HDS-010-SDS-010-SMS-040
```

So sharing is intended. The defect is the cost it imposes on each sharer.

## Finding

`tests/FS-310-HDS-010-SDS-010-SMS-030.sh` dispatches **every** `*.sh` in its case
directory:

```
mapfile -t cases < <(find "${case_root}" -maxdepth 1 ... -name '*.sh' -print | LC_ALL=C sort)
```

`tests/lib/FS-310-HDS-010-SDS-010-SMS-030/` holds two files: the row's own
`primary.sh`, and the shared FS-270 case. The shared case is expensive —
measured at over 4 minutes of CPU on its own:

```
$ time NETWORK_REPO_DIRECT_TEST_OK=1 bash \
    tests/lib/FS-310-HDS-010-SDS-010-SMS-030/FS-270-HDS-010-SDS-010-SMS-040.sh
real 4m0.294s   user 3m35.884s
```

so the entrypoint does not complete inside 300 s:

```
$ NETWORK_REPO_DIRECT_TEST_OK=1 timeout 300 bash tests/FS-310-...-SMS-030.sh
exit=124
```

`network-labs` records that timeout as
`FS-310-HDS-010-SDS-010-SMS-030: FAIL`. The row's own case passes
(`PASS FS-310-HDS-010-SDS-010-SMS-030 row-local: all predicates verified`), so
the whole failure is the shared case's runtime.

## Note on `FS-320-HDS-010-SDS-010-SMS-040`

That trace's case directory contains only the shared FS-270 file and no case of
its own, so its entrypoint runs nothing of its own either. If that is intended,
it is fine; if not, it is the same shape of gap.

## Requested fix (pick one)

1. Reduce the shared case's runtime so a sharer fits the budget; or
2. Let a trace's dispatcher skip shared cases it does not own, keyed on the
   `GAMP-ID:` headers rather than on the directory it happens to sit in; or
3. Give the heavy shared case its own entrypoint and have only the owning trace
   run it.

Whichever is chosen, the per-sharer cost is what needs bounding: a shared case
that takes 4 minutes makes every additional sharer unaffordable to test.
